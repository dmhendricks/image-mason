Image Mason

Version {{version}}

A self-hosted API that optimizes, converts, resizes and crops JPEG, PNG, WebP, AVIF and JPEG XL images, and can host the results at temporary URLs. Every lossy result is the smallest file that meets a perceptual quality target (SSIMULACRA2), so a preset describes how the image looks, not an encoder setting.

Quick Start

$ curl -sS --data-binary @photo.jpg -o photo.min.jpg \
    {{origin}}/api/v1/transform
$ curl -sS -G --data-urlencode "url=https://example.com/photo.jpg" \
    -o photo.min.jpg {{origin}}/api/v1/transform

Every job is a POST to transform, with the image as the body or named by url. With no parameters, you get the same image back, optimized. Add parameters to resize, crop or convert it in the same call. If the server has an API key, send it in the X-Api-Key header.

Features

Convert

$ curl -sS --data-binary @photo.jpg -o photo.webp \
    "{{origin}}/api/v1/transform?format=webp"
?format=avifAVIF; also jpeg (or jpg), png, webp and jxl
?format=autoJPEG if the input is a PNG photo with no transparency; otherwise unchanged
?format=webp&width=800WebP, 800 wide

The result is still optimized: the smallest file that meets the quality preset.

Resize

$ curl -sS --data-binary @photo.jpg -o photo-1200.jpg \
    "{{origin}}/api/v1/transform?width=1200"
?width=12001200 wide
?height=600600 high
?width=300&height=700Exactly 300 × 700
?width=1200&height=1200&fit=containWithin 1200 × 1200
?width=400&height=400&fit=cover400 × 400, edges cropped
?width=400&height=400&fit=cover&position=attentionKeeping the most interesting part
?width=1200&upscale=falseAt most 1200 wide

With one side, the other follows the image's shape. With both, fit decides how a landscape photo reaches a portrait size (the dashed box):

Smaller images are enlarged to the size asked for. Add upscale=false to only shrink them.

Crop

$ curl -sS --data-binary @photo.jpg -o square.jpg \
    "{{origin}}/api/v1/transform?crop=80,0,480,480"
?crop=80,0,480,480The 480 × 480 square 80 pixels from the left
?crop=80,0,480,480&width=200That square, resized to 200 × 200
?crop=0,0,1200,630&format=webpThe top-left 1200 × 630, as WebP

crop is left,top,width,height in pixels, as the image is displayed. It's cut first, so width and height resize the area. An area past the image's edges gets 400.

Quality

PresetMin scoreResult
losslessIdentical pixels; only the encoding is optimized
high{{highScore}}No visible difference in place at 1:1
medium{{mediumScore}}No visible difference side by side at 1:1
low{{lowScore}}Barely visible difference side by side
?quality=lowA preset; this server's default is {{defaultQuality}}
?minScore=90A custom floor instead of the preset's

Scores are SSIMULACRA2, from 0 to 100, where 100 is identical. A lossy result is the smallest file that scores at least the floor.

Store

$ curl -sS --data-binary @photo.jpg \
    "{{origin}}/api/v1/transform?store=true&format=webp"
200 · application/json{
  "output": "{{origin}}/images/f100579f….webp",
  "size": 47521,
  "width": 640,
  "height": 427,
  "expiresAt": "2026-10-28T16:32:24-04:00",
  …
}
?store=trueJSON with the result's URL and statistics, instead of the image
?store=true&filename=banner.jpgStored under that name, replacing one already there
?store=true&keepOriginal=trueThe input stored too, as input
?source=f100579f….jpgStart from a stored image instead of a body

Stored images are served at /images/{name} to anyone with the URL, then deleted when they expire: after {{ttlMinutes}} minutes on this server, at the time in expiresAt.

The server's IMAGE_MASON_IMAGE_TTL_MINUTES sets how long, and when storage reaches IMAGE_MASON_MAX_STORE_SIZE, the oldest go first.

POST /api/v1/upload stores an image unchanged, so several jobs can use it as source without sending it again.

Parameters

urlDownload the image from this URL instead of reading the body.
sourceA stored image's name, instead of the body.
qualitylossless, high, medium or low. Default {{defaultQuality}}.
minScoreA custom floor, 0 to 100, instead of the preset's.
formatjpeg, png, webp, avif, jxl or auto. Default: the input's.
cropThe area to keep, left,top,width,height. Cut before resizing.
width, height1 to 65535. With one, the other follows the shape.
fitWith both sides: fill (default), contain or cover.
positionWith fit=cover: center (default), attention or entropy.
upscalefalse only shrinks, leaving smaller images as they are. Default true.
storetrue returns JSON with the stored result's URL.
filenameThe stored name, such as banner.jpg. Needs store=true.
keepOriginaltrue stores the input too. Needs store=true.

Parameters the server doesn't know get 400, so a typo never goes unnoticed.

Response Headers

The image comes back with these headers. With store=true, the JSON has the same values.

X-Image-Mason-QualityThe preset used
X-Image-Mason-Original-SizeInput size in bytes
X-Image-Mason-SizeOutput size in bytes
X-Image-Mason-Size-Change-PercentChange from the input size; negative is smaller
X-Image-Mason-Original-DimensionsInput width x height
X-Image-Mason-DimensionsOutput width x height
X-Image-Mason-MethodHow it was made, such as jpegli-d1.15 or crop+resize+cwebp-q93
X-Image-Mason-ScoreSSIMULACRA2 score of a lossy result
X-Image-Mason-Min-ScoreThe floor the result had to meet
X-Image-Mason-Is-PhotoFor PNG inputs: whether it looks like a photo with no transparency
X-Image-Mason-Duration-MsProcessing time
